Which Metrics Actually Work for Financial RAG?
Day 7/14 · RAG From Zero → Production
✓ USE THIS
Exact Match
Does the gold answer string appear anywhere in the prediction? Simple, fast, no model needed.
Gold: "10.3%"
Prediction: "…margin for Corning is 10.3%."
Result: ✓ Match
✓ USE THIS
Numeric Match (±1%)
Extract numbers from both strings. Do they agree within 1% tolerance? Handles unit variations.
Gold: "$7.2B" → 7.2
Prediction: "$7,200M" → 7200 / 1000 = 7.2
Result: ✓ Within 1%
✗ MISLEADING
ROUGE-L
Lexical overlap. Built for paragraph summarisation. Punishes full sentences against one-word golds.
Gold: "10.3%"
Prediction: "The 3-year average is 10.3%."
ROUGE-L: 0.21 ← looks wrong, is right
~ COMPLEMENTARY
Self-RAG Confidence
LLM judges its own answer against retrieved context. No gold label needed — useful for production monitoring.
No gold required
Avg on FinanceBench: 0.87 / 1.0
Cost: +1 LLM call per query
~ USE CAREFULLY
BERTScore F1
Semantic similarity using contextual embeddings. Better than ROUGE but still diluted by verbose answers.
Avg on FinanceBench: 0.28 / 1.0
Better than ROUGE, still low
Cost: ~1.5 GB model, local
✗ DOMAIN MISMATCH
NLI Hallucination Rate
Entailment check: does the cited quote prove the sentence? Fails on arithmetic — can't derive "10.3%" from a raw table.
Correct answer → hallucination=1.0
NLI can't do math
Useful for prose, not financials
💡
The lesson: Borrowing NLP benchmark metrics for financial RAG gives you misleading signal. ROUGE was designed for news summarisation. NLI was designed for natural language inference — not balance sheets. Exact Match + Numeric Match are simpler, faster, and actually tell you if the answer is right. Domain-appropriate eval is half the engineering work.
